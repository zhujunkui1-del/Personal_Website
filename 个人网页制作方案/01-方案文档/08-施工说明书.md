### 空状态设计
项目未完成时**不编写替代内容**，用排版化空状态诚实呈现：

```
┌──────────────────────────────────────┐
│ 01 PROJECT                           │
│                                      │
│ 知 遇                                │  ← 大号等宽/黑体项目名
│ ZHIYU                                │
│                                      │
│ 在你认识一个人之前，让 Agent 先认识 TA  │  ← GitHub 简介原文
│                                      │
│ ────────────────────────────────     │
│ TYPE      AI AGENT / FULL-STACK      │
│ STATUS    IN PROGRESS                │  ← 如实标注
│ SOURCE    GITHUB ↗                   │
└──────────────────────────────────────┘
```

**设计要点**：
- 用**大字排印**填满栏目，而不是留一片空白
- `STATUS / IN PROGRESS` 如实标注项目状态
- 视觉上与默认图（白底虚线线稿）语义一致 —— 都是"等待填充"
- **不造假内容**：宁可用排版撑场，也不编造项目描述

## 四、视觉规范

### 色彩（修正版）
参考图中黄与蓝是**并用**关系，不是"唯一强调色"。

| 色 | 角色 | 用法 |
|---|---|---|
| 酸性荧光黄 `#E8FF00` | **主强调** | 芯片、高亮、当前项、斜带 —— 每页 1–2 处 |
| 电光蓝 `#1E3AFF` | **大色块** | 通栏带、大形状 —— 每页 1 处 |
| 碳黑 `#0D0D0D` | 结构与文字 | 巨字、1px 细线 |
| 纸白 `#F9F9F9` | 基底 | 全站背景 |
| 洋红 `#FF2B8A` / 橙红 `#FF4422` | 小警报 | 点缀 |

### 字体
| 用途 | 字族 | 状态 |
|---|---|---|
| 展示级标题 | **Archivo Black** | 需自托管 woff2（约 100KB） |
| 正文 / 长文 | **Inter** | 需引入 |
| 界面 / 元数据 / 导航 | **JetBrains Mono** | 需引入 |
| 中文 | 思源黑体 Heavy + 思源黑体 Regular | 需引入 |

> ⚠️ **巨型中文标题不能用等宽字，也不能做负字距**（汉字会粘连）。
> 中文巨字的紧凑感靠**思源黑体 Heavy 的字重** + **压缩行高 0.86** 实现。

### 铁律
1. **零圆角、无阴影、无柔和渐变**
2. **每页只有 2–3 个视觉爆点**，其余安静有序
3. **1px 结构细线是骨架，必须保留**
4. **内容层放开撞色，外壳层克制**
5. **动效禁用回弹** —— 统一 `cubic-bezier(0.22, 1, 0.36, 1)`

详见 `04-视觉纪律.md`。

#### 可见性模型

```
visibility: 'public' | 'private'
```

| 状态 | 谁能看 | 出现在哪 |
|---|---|---|
| `public` 公开留言 | 所有人 | 留言墙「公开墙」标签 |
| `private` 悄悄说 | **仅站长**（登录后） | 留言墙「悄悄说」标签 |

#### 表单（选择器形式）

```
┌────────────────────────────────────────────┐
│ 昵称  [_______________________________]    │
│ 内容  [_______________________________]    │
│       [_______________________________]    │
│                                            │
│ 可见性   [ 公开留言 ]  [ 悄悄说 ]           │  ← 两个方形芯片
│                          当前项黄底黑字      │
│                              [ 提交 ]       │
└────────────────────────────────────────────┘
```

**措辞**：`公开留言` / `悄悄说`（口语化，降低访客心理门槛）

#### 三个展示规则

1. **私密留言在公开墙上完全不显示** —— 不留痕迹、不显示占位卡、不显示计数
2. **私密区需要站长登录** —— 未登录时该标签不可见
3. **提交私密后** —— 访客看到「已悄悄送达」确认，不跳转到公开墙

#### 所有者管理

登录后，**每张留言卡上直接出现两个操作**：

| 操作 | 作用 |
|---|---|
| **公开 ⇄ 私密** | 双向切换。公开转私密即从墙上撤下；私密转公开即重新上墙 |
| **删除** | 永久删除 |

> ⚠️ **不设"隐藏"状态**。原方案里的「隐藏」与「转为私密」功能重叠，
> **已合并** —— 撤下一条留言的方式就是转为私密。

```sql
CREATE TABLE messages (
  id          SERIAL PRIMARY KEY,
  nickname    TEXT NOT NULL,
  content     TEXT NOT NULL,
  visibility  TEXT NOT NULL DEFAULT 'public',   -- 'public' | 'private'
  created_at  TIMESTAMPTZ DEFAULT now(),

#### 安全注意

- 私密留言的**读取接口必须校验登录态**，不能靠前端隐藏
- 提交接口需做长度限制与内容转义（防 XSS）
- 未登录时 `/api/messages?visibility=private` 必须返回 401

> ⚠️ **已知风险**：无防护的公开留言墙会被机器人刷。
> 作者决定先不设防，但**代码必须预留接入点** ——
> 后续可低成本加 Cloudflare Turnstile 或蜜罐字段 + 频率限制，不需重构。
